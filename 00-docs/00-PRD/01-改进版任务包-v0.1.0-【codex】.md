# 人员工时与实施费核验 · 改进版任务包

版本 0.1.0 · 2026-11-06 · 状态：用户确认范围，模拟规则待业务定稿

2026-11-06 v0.2.0修订：用户明确“录入啥就是啥”，取消应用内认定与复核流程。以下初版复核模型、R4及复核验收条款作为历史依据保留，当前以录入量直接核验、编辑保存即重算、更正历史留存为准。旧认定量与顺序不进入主界面累计；编辑有效旧记录时解除其旧审批状态，不清除历史。三类检查、重复排除、缺项提示、模拟规则边界不变。

本文件为首版实施依据，原 Opus v3 保留作算法来源，不再要求所有旧口径原样移植。实现不得把模拟参数或新增设计写成领导已批准规则。

## 1. 目标与边界

本次起始项目逐项录入、统一积累，针对同一人员的跨项目投入、实施期间、职称与计费开展三类检查。机器给出来源与待核项，审核人员记录处理意见。无历史项目追录、OCR、模型调用或正式审减自动决定。当前规则模式固定为模拟，正式参数批准后另行版本更新。

独立本地服务＋SQLite＋桌面 Web，默认仅监听本机。业务数据在服务端统一保存；多人修改使用版本冲突检测，不能后保存覆盖前保存。首版复核人手工填写，仅作留痕，不等同账号认证或电子签名。实际内网开放需确认服务器、访问控制、备份责任及并发流程；本轮不宣称内网部署完成。

## 2. 最小数据模型

| 对象 | 字段 |
|---|---|
| 项目 | 内部ID、项目编号、名称、建设起止、实施起止、实施期依据 |
| 人员 | 内部ID、单位、工号、姓名、职称、证明依据、职称有效起止；同名不同内部ID分开，单位＋工号防重复 |
| 申报 | ID、人员ID、项目ID、人员投入起止、数量、工日/工时/人月、申报日期、计费等级、申报单价、单价单位、合同对应职称/允许等级/依据单价/依据单位/依据与有效期间、重复处理状态 |
| 复核 | 条目状态、认定原单位数量、审核人、理由、业务处理序号、系统时间；原申报量不被认定量覆盖 |
| 配置 | 小时/工日、人月/工日（默认空）、加班参考小时、平均月天数、容差、规则版本及模拟模式 |
| 日历 | 年份、休息日、补班日、来源；输入冲突拒绝 |
| 日志 | 修订号、操作者、动作、时间、前后完整状态；恢复也记日志 |

数据允许缺项保存供补录；非法日期、负数量、未知单位、NaN、引用不存在对象、重复ID拒绝。缺项的相关检查不得判通过。

## 3. 规则

### R1 跨项目容量初筛

人员身份必须明确，不能按姓名合并。单位换算来源于模拟配置，缺人月换算则待核。完整人员期间优先；完全没填人员日期且实施期完整时可作“实施期估算”，但保留日期待核。半填或逆序不得拼接或静默扩大区间。建设期不能代替实施期。

按人员枚举起止边界紧窗口，仅汇总完整落入窗口的条目。C0=日历工作日；C1=C0＋模拟月加班小时/小时每工日×日历天数/平均月天数；C2=max(日历天数,C1)。这三条仅为参考线：常规范围、需说明额外投入、重点核查、高负荷核查。不得使用“法定通过”“物理不可能”。每个窗口列出条目ID和构成、规则版本、日期口径、日历来源；数值显示四舍五入、比较使用原精度。

同人同项目同期间疑似重复默认保留申报，显示累加与去疑似重复的假设结果；已明确追加不从假设结果中删除。用户明确重复后保留原记录但不计入。撤销、退回记录不占用认定量；保留可检索记录。人员三类检查摘要与数据缺项并列，避免遗漏记录被“绿灯”掩盖。

### R2 实施期间

分开验证建设与实施期间关系、人员投入是否超实施期、单条数量是否超过所在期间参考容量。实施期或其依据缺失、人员期间不完整时输出待核。实施期外投入单列异常，不自动把超出天数乘单价当审减额；无逐日投入不能按比例拆量。

### R3 职称与计费

核对人员职称证据、有效期与申报投入期；核对合同依据中职称、可计费等级、单价、单位与适用期。等级采用明确映射或人工录入的有来源对应关系，不能靠“高级/中级”字符串大小猜定级。同单位下可显示单价差，数量×单价需单位一致且依据完整；缺项不算确定金额。

### R4 认定与复核

状态：待复核、待补资料、已认定、退回、撤销；“已认定”必须填写认定量、复核人、理由和处理序号。该状态仅记录人工输入，不表示系统批准结算。序号在全库唯一，认定量不得超申报量。每次更正均保留历史并重算。

对当前申报，按处理序号选前序已认定记录。采用同一窗口约束比较前序占用与加入当前后的容量，显示当前可容纳的模拟量及限制窗口；不能把所有相交条目的总量直接扣在当前期间。前序资料不足、待核重复、顺序缺失等则不提供确定剩余量。认定顺序未获正式批准，剩余与差额均标模拟参考；不同窗口差额不可相加作为总审减。

## 4. 操作闭环与 UI

项目/人员 → 申报录入 → 三类核验 → 来源明细 → 人工复核 → 更正重算 → 导出/备份。模拟数据在独立数据库，正式空台账不预置虚构人物。

采用 Astra DESIGN.md 1.1.38 的桌面规范：React、daisyUI、Tailwind、Phosphor 本地图标；系统字体回退，不复制授权不明字体。用户后续明确以图形轨迹为主：默认亮色、可选深色，左侧选人员、中央跨项目泳道、右侧证据面板，记录表在泳道下方；只有一条主工具栏。持续录入后同步更新轨迹与数量核验，点击交叉区段查看关联项目。按用户补充要求，保留蓝色主题，容量风险以低饱和绿、赭黄、橙、红的浅底、细边和文字区分；人员、时间条与容量预警带保持一致。时间条按核查窗口关联记录着色，预警带定位对应核查时段；期间交叉独立置于时间带，标记该段工时未知；选中时仅在关联申报条内部绘制灰色交叉切片，不再铺满所有泳道。整段累计用日期括号、项目小标签与完整申报条联动高亮，与交叉部分独立显示，模拟与待核状态清楚。图示只表现申报起止和全期总量，不把其均摊为每日实际工时。

必须支持创建与修改项目/人员/申报、搜索与筛选、重复判断、复核及撤销、更正历史、规则和日历维护、CSV结果导出、打印明细、JSON备份与验证后恢复。数据保存失败保留输入，恢复前自动备份，陈旧版本写入拒绝。

## 5. 验收与阶段

M1 规则与数据：覆盖正常并行、跨项目超量、不同期、同名异人、建设期内实施期外、单条超量、等级/单价错配、资料缺失、混合重复、工时与人月、认定占用、更正撤销、日历、边界和精度。

M2 实际页面：手工建立项目/人员/申报，保存刷新仍在，检查三类证据，复核留痕，修改后重算，备份恢复，导出打印，亮暗主题、键盘弹窗、1366×768桌面。

M3 业务试用：真实两个项目及合同/人员证据由业务方提供；与人工结论比对。正式规则、真实项目验收、Office导出查看、内网多机与权限验收分别记录，不以构建或模拟通过代替。

首版暂缓 Opus 的风险打分、平均摊每日负荷、日期放宽稳健性与“首要核查项目”归因，以三类核验和人工留痕主线优先。它们不是领导明确要求的首期必选项。
