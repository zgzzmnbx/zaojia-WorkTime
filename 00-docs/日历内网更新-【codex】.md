# 日历内网更新

在“设置 → 日历核查与内网更新”填写内网日历服务地址，点击“检查内网更新”，核对年度变化后保存。地址保存在当前台账，实际与模拟台账独立。检查成功会默认勾选新增或有变化的年度，保存时生成更正历史并重算工时。连接失败可继续使用之前保存的日历。

## 使用本工具作为内网日历服务

内网部署本工具后，“维护本年度”保存的日历可以供其他实例读取。读取接口为该实例的 /api/calendar-feed。例如项目已有内网入口对应的地址为 http://10.54.9.47:8791/api/calendar-feed，需该服务器实际部署了本次更新且当前电脑能访问。此地址是部署位置示例，本次开发机试连该内网入口超时，尚未完成该服务器实测与升级。

由负责日历维护的人在中心实例核对通知、修改年度日期并保存，其他实例检查内网更新后即可取得新安排。同一内网实例的所有使用者共享台账，保存后刷新页面即可看到更新。

## 对接单位现有服务

更新接口通过 HTTP 或 HTTPS GET 返回 UTF-8 JSON。当前支持格式如下，年度中未列出的日期按普通周一至周五、周六周日处理。

```json
{
  "format": "expert-hours-calendars",
  "version": 1,
  "bundle_version": "2026-11-19",
  "calendars": [
    {
      "year": 2026,
      "source": "对应年度完整放假调休通知、文号和网址",
      "holidays": ["2026-01-01", "2026-01-02", "2026-01-03"],
      "makeup_days": ["2026-01-04"]
    }
  ]
}
```

以上日期仅展示字段格式，实际接口须返回各年度完整安排，否则会误判该年度已完整维护。每个年度在保存时整体替换，中心服务修改日期后应保留完整年度。

接口限制为内网或本机地址，最大响应 1 MB，连接与读取超时 5 秒，HTTPS 使用正常证书校验。HTTP 跳转会提示填写最终接口地址。数据请求由本工具后端发出，日历服务只接收获取日历的 GET 请求。返回网页、日期冲突、同年重复数据等会显示错误，原日历继续使用。

勾选“每周自动同步服务器日历”并保存后，本工具后端每分钟检查到期情况，每周从已配置的服务器读取一次。首次启用或变更地址后会在下一次后台检查时尝试同步。连接失败一小时后重试，旧日历继续使用。运行此功能需要本工具后端保持运行，浏览器可以关闭。

自动同步会整体替换源服务提供的同年日历，同时保留源服务未包含的其他年度。变更以“系统（日历自动同步）”记入更正历史，读取后若发现源地址被更换、同步被关闭或保存时台账版本冲突，将保留新的用户修改。检查时间和失败原因保存在各台账自己的状态表，未发生日历变更时不会增加台账版本。

暂时离线时也可以保存内网地址和自动同步设置，网络恢复后后台会继续尝试。已有源数据应为完整年度安排，新年度安排需要中心服务器取得公布的通知后发布。当前仅完成客户端定期同步，本次开发机对服务器网页访问超时，SSH 在账号认证前被关闭，服务器自身的数据获取渠道、日历更新部署和运行状态仍待在可连接环境核查。
